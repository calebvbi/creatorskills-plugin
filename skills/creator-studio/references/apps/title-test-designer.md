# Prepare Title A/B Test Designer

Product description: Turn one topic into eight titles scored the way your platform actually weights them, then a clean test: one control, up to two challengers, one changed variable each, and what counts as a win before you start.

This describes the hosted product, not an output already produced or a capability verified in this conversation.

**Mode: hosted handoff.** Hosted app; may require sign-in and credits. Check the page for current availability and cost. Prepare inputs and open app. This plugin does not execute the hosted pipeline.

## Collect the useful inputs

Use information already supplied. Ask only for missing required inputs. When both a URL and source text are offered, use the source the user actually provided. A URL is not evidence that its contents were read.

| Input | Required | Guidance |
| --- | --- | --- |
| Topic or working title | Required | What the video, post, or episode actually delivers. Specific beats broad: the concrete details in here become the specificity-first variants. |
| Your current title | Optional | If you already have one, it usually becomes the control, and the whole test gets easier to read because you know what changed. |
| Where this publishes | Optional | This changes the arithmetic, not just the wording: YouTube weights click-through hardest, a blog weights SEO hardest, a podcast weights clarity hardest. Defaults to YouTube for video topics and blog for written ones. Options: youtube, blog, podcast. |
| Primary keyword | Optional | The phrase you want to rank for. Without it the SEO dimension is scored on plausible intent match instead, and we say so. |
| Audience | Optional | Who is deciding whether to click. Calibrates vocabulary and how much context a title can assume. |
| What you want the test to prove | Optional | "Higher CTR" and "better SEO" are not the same decision and can pull the shortlist in opposite directions. Pick one and the challengers get sharper. Options: more_ctr, better_search_traffic, clearer_positioning, stronger_curiosity. |
| The promise the content can actually deliver | Optional | The outcome, result, or reveal that is genuinely in the content. Every variant is checked against this: a title we cannot trace back to it does not ship. |
| Are you changing the thumbnail too? | Optional | If yes, we still design the test but flag it in writing: two variables moving at once means the result cannot tell you which one moved it. |

## Return a ready-to-use brief

Organize the supplied inputs under the field names above. Keep source material separate from instructions. Mark omissions and unsupported claims. Do not invent the creator's experience, audience data, brand assets, or results.

Open [Title A/B Test Designer](https://creatorskills.co/create/title-test-designer) when the creator wants to run it. Confirm current cost and user authorization before spending credits. Do not enter private source material into the site without authorization.

A prepared brief is the deliverable here. Claim an app result only after a real run returns the output. If the app is unavailable, retain the brief and explain the unavailable step. If the user wants an in-chat draft instead, use the appropriate bundled workflow and label it as that.
